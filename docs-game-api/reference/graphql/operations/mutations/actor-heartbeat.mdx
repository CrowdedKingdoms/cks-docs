Application liveness heartbeat for the authenticated user's existing actor rows in an app. Refreshes actors.updated&#x005F;at so the user stays host-eligible, then returns the freshly-elected host so a client can fold its poll and heartbeat into one round-trip. This is not proof of a live Buddy session and does not refresh the separate Buddy presence lease used by security-sensitive artifact/compute occupancy gates.


```graphql
actorHeartbeat(
  appId: BigInt!
): GameHost
```


### Arguments

#### [<code style={{ fontWeight: 'normal' }}>actorHeartbeat.<b>appId</b></code>](#app-id)<Bullet />[<code style={{ fontWeight: 'normal' }}><b>BigInt!</b></code>](/reference/graphql/types/scalars/big-int.mdx) <Badge class="badge badge--secondary badge--non_null" text="non-null"/> <Badge class="badge badge--secondary " text="scalar"/> \{#app-id\} 
The app (game) whose actors owned by the authenticated user should be kept fresh, as a BigInt decimal string. Also the app the returned host is elected for.




### Type

#### [<code style={{ fontWeight: 'normal' }}><b>GameHost</b></code>](/reference/graphql/types/objects/game-host.mdx) <Badge class="badge badge--secondary " text="object"/> 
The elected host user of a game (app). Election is deterministic across all cks-game-api replicas: among actors that are still fresh (recently heartbeated), the user whose earliest actor was created first wins, with a uuid tiebreaker. Row lifecycle is owned by Buddy (cks-udp-api); liveness (updated&#x005F;at) is owned by game-api's actorHeartbeat mutation.
