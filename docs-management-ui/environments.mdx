# Apps on the shared platform

Every customer app runs on the **shared Game API** — a managed, multi-tenant endpoint scoped by your **`appId`**. You do not provision VMs, pick datacenters, or wait for a dedicated stack.

:::tip[Primary path for new studios]
If you are standing up your **first game**, start with **[Create your first app](/management-ui/create-your-first-app)**. That wizard registers the app on the shared platform and it is **immediately usable** after create.
:::

After create, use **[Connecting to your app](/management-ui/connecting)** for endpoints, tokens, and client configuration. Billing and usage limits are covered in **[Shared environment & billing](/management-api/shared-environment)**.

## How routing works

| Concept | Detail |
| ------- | ------ |
| **Shared endpoint** | One Game API fleet (`https://ck.prod.crowdedkingdoms.com`), with a host per datacenter. |
| **App scoping** | Traffic is isolated by `appId` — your players only see your app's world data. |
| **Discovery** | Read `gameApiUrl` from the app record or `mintAppToken`; or call public `platformConfig` for tier defaults. |

Programmatic discovery (no auth):

```graphql
query {
  platformConfig {
    sharedGameApiUrl
    sharedGameApiWsUrl
    freeAppsPerOrg
  }
}
```

Per-app routing after create:

```graphql
query {
  app(appId: "<your-app-id>") {
    appId
    deploymentTarget   # "shared"
    runtimeStatus      # "active" — immediately usable
    gameApiUrl
  }
}
```

## App dashboard

Open **`/orgs/:orgSlug/apps/:appSlug`** for studio operations on a single game:

- **Connection info** — `gameApiUrl` and WebSocket URL for clients (same shared host for all apps on the tier).
- **Access tiers** — marketplace and entitlement settings.
- **Granted users** — who can play or manage the app.
- **Runtime status** — `active`, or a denial reason when wallet, caps, or subscription block traffic.

## Free tier and wallet

- **Free allowance:** an organization's apps share one free allowance each calendar month (UTC), and making more apps does not add to it. **[Free tier](/management-api/shared-environment#free-tier)** lists the amounts.
- **Free data tier:** the organization's free data out and data in follow its tier, from 15 GB up to 500 GB a month each ([Free data tiers](/management-api/shared-environment#free-data-tiers)). The org's **Plan and Usage** tab shows this month's tier, next month's, and each tier's condition. A member who manages billing gives the studio's own domain there (a member's confirmed account email must be at it), and **Answer the six questions** opens the project profile. A tier the organization reaches applies from the start of the next month.
- **Above the allowance:** usage debits the organization **wallet** at the published rates. If the wallet cannot cover it, CK denies each app that keeps using a meter whose allowance is used up, within about a minute.
- **Auto-billing:** an optional saved card tops up the wallet when the balance runs low.

Top up or configure auto-billing from the org **Wallet** tab before heavy testing or launch.

## Permissions and tokens

- **Org members** manage apps through the UI according to org RBAC.
- **Org API tokens** (created under the org **Tokens** tab) can call the same Management API mutations your user can, for automation — see the [Management API schema reference](/management-api/reference/graphql-overview) for `createApp`, `mintAppToken`, and related types.

Keep tokens secret; they grant org-level power equivalent to a highly privileged member.

## Dedicated environments (not self-service)

**Dedicated** and **developer sandbox** stacks (isolated Game API + database + Buddy per org) were **retired without replacement** — not moved behind the operator console. There is no per-tenant stack to provision and no API for one. Contact Crowded Kingdoms if you need enterprise isolation.

- Customer integration docs: **[Shared environment & billing](/management-api/shared-environment)** and **[CrowdyJS → Loading an app's Game API](/crowdyjs/shared-environment-routing)**.
- Every app uses the shared platform (`publishAppToShared`); customer-provisioned environments were retired.

## Troubleshooting

| Symptom | What to check |
| ------- | --------------- |
| Cannot connect to Game API | Mint an **app-scoped token** (`mintAppToken`); identity session tokens are rejected for gameplay. |
| `runtimeStatus` denied | Wallet empty, spend cap hit, or subscription lapsed — see [Shared environment & billing](/management-api/shared-environment). |
| Wrong Game API URL | Use `app.gameApiUrl` or `platformConfig.sharedGameApiUrl`. Do not compose a hostname. |
| Token expired | Call `refreshAppToken` on the Management API before retrying gameplay. |
